# C4 and arc42 views

> **Audience:** anyone who needs the whole system on one page, from who uses it down to the
> classes on the query path. [overview.md](overview.md) covers the design principles, the
> module table and the data model. This page adds the four C4 zoom levels and the arc42
> building-block, runtime and deployment views, and it links back to overview.md instead of
> repeating it.

The diagrams use C4 notation inside ordinary Mermaid flowcharts. Mermaid has a `C4Context`
syntax, but it is still experimental and lays out poorly at this size. Every box names a real
file, class or workflow, and `diagrams.yml` parses every block on each push. Dashed lines and
dashed boxes are optional: nothing fails without them.

it still works, knowledge explains it, and operations runs the course on GitHub. The

## Level 1: system context

Who uses nanorag, and what does it reach outside itself?

Nothing outside nanorag is needed at runtime. PyPI is needed once, at install time, and
GitHub hosts the course around the code. Amazon Bedrock, the Claude API, Hugging Face and
MultiHop-RAG connect through the interfaces the offline defaults already implement: `Hit`,
`BaseEmbedder`, `.rerank()` and `BaseGenerator`. Swapping one in changes the retriever or the
reader. The harness, the metrics and the eval set stay the same.

trace store live inside the Python process, but they have their own schema and lifecycle, so
they get their own boxes. The lab sandbox and the eval gate runner exist only on a GitHub

## Level 4: code

### Query-path classes

The swappable interfaces are `BaseEmbedder`, `BaseGenerator` and the reranker protocol. The
reranker protocol has no base class in the code; it is duck-typed, and the diagram draws it as
an interface. `RagPipeline` receives its index and embedder and never imports `store`, so a
Bedrock Knowledge Base retriever that returns `Hit` can replace the local index.

```mermaid
classDiagram
    direction LR
    class RagPipeline {
        +index
        +embedder
        +cfg: RetrievalConfig
        +generator
        +reranker
        +trace_store: TraceStore
        +name: str
        +variant(name, **cfg_updates) RagPipeline
        +run(query, qid, persona, acl_groups) Trace
    }
    class RetrievalConfig {
        +n_candidates = 100
        +k = 8
        +evidence_token_cap = 6000
        +fusion: rrf|weighted|dense|lexical
        +alpha
        +rerank: none|cross|late
        +rerank_depth = 50
        +ann, ef_search
        +acl_groups, filter_mode: pre|post
    }
    class HybridRetriever {
        +index
        +embedder
        +search(query, cfg) List~Hit~
    }
    class InMemoryIndex {
        +db: sqlite3.Connection
        +upsert(chunks, vectors, version, embedder_tag) int
        +tombstone(chunk_ids, version) int

        +fit(pairs, labels)
        +rerank(query, hits, depth)
    }
    class LateInteractionReranker

    class BedrockReranker
    class BaseGenerator {
        <<abstract>>
        +generate(query, packed) Answer

    class ExtractiveGenerator
    class UngroundedGenerator
    class BedrockGenerator
    class AnthropicGenerator

        +blocks
        +resolve(sid) chunk_id

        +citations
        +sufficient

        +trace_id, qid, query
```

### Retrieval store schema

Taken from `store.SCHEMA`. Blue/green deployment is rows in `index_versions` plus a pointer in
`aliases`. `embedder_tag` is the only thing that catches a mixed-encoder index, because cosine
returns well-formed scores for vectors from two different models.

```mermaid
erDiagram
    index_versions ||--o{ chunks : "holds"
    aliases }o--|| index_versions : "points at"
    chunks ||--|| chunks_fts : "mirrored into"

    chunks {
        int row_id PK
        text chunk_id "doc_id + ordinal + content hash"
        text index_version "UNIQUE with chunk_id"
        text doc_id
        int ordinal
        int n_chunks
        text title
        text heading
        text source
        text published
        text tenant
        text acl "json array of groups"
        text content_hash
        text embedder_tag "pinned encoder identity"
        text text
        blob vector "float32"
        int tombstoned "soft delete"
    }
    chunks_fts {
        text text "FTS5 indexed"
        text title "FTS5 indexed"
        text heading "FTS5 indexed"
        text chunk_id "UNINDEXED"
        text index_version "UNINDEXED"
    }
    aliases {
        text name PK "e.g. live"
        text index_version
        text swapped_at
    }
    index_versions {
        text index_version PK
        text embedder_tag
        text chunker
        text created_at
        text note
    }
```

## Runtime view

Six runtime paths matter. Two run in the learner's kernel (R1, R2), two run on GitHub (R3,
R4), and two are control loops inside the toolkit (R5, R6).

### R1: cold start with `quickstart()`

```mermaid
sequenceDiagram
    autonumber
    participant U as Notebook / run_eval.py
    participant Q as nanorag.quickstart
    participant C as corpus
    participant K as chunking
    participant E as LsaEmbedder
    participant I as InMemoryIndex
    participant P as RagPipeline

    U->>Q: quickstart(**TUNED)
    Q->>C: build_corpus()
    C-->>Q: CorpusBundle: 484 docs, 243 questions, personas
    Q->>K: chunk_corpus(docs, "structural")
    K-->>Q: 2,430 Chunk with stable ids
    Q->>E: fit(whole documents)
    Note over E: SVD latent space fitted on docs,<br/>then chunks encoded into it
    Q->>E: encode_documents(chunk texts)
    E-->>Q: float32 matrix, tag lsa@1.0:d96
    Q->>I: upsert(chunks, vecs, "v1", embedder_tag)
    Note over I: rows + FTS5 mirror written,<br/>ACL cache cleared
    Q->>I: set_alias("live", "v1")
    Q->>P: RagPipeline(idx, emb, RetrievalConfig)
    P-->>U: bundle, idx, pipe  ·  about 0.6 s
```

### R2: one query through `RagPipeline.run()`

Each stage is timed into `stage_ms`. `trace_id` is a UUID5 of the pipeline name, the qid and
the query, so re-running a query produces the same id and two runs can be diffed with
`diff_traces`.

```mermaid
sequenceDiagram
    autonumber
    participant U as Caller
    participant P as RagPipeline.run
    participant H as HybridRetriever
    participant I as InMemoryIndex
    participant R as ProxyCrossEncoder
    participant X as pack_context + build_prompt
    participant G as ExtractiveGenerator
    participant T as TraceStore

    U->>P: run(query, qid, acl_groups)
    P->>H: search(query, cfg)
    Note over H: legs run one after the other
    H->>I: LexicalRetriever: lexical(query, N=100, acl)
    I-->>H: FTS5 MATCH ranked by bm25()
    H->>I: DenseRetriever: exact_vector or ann_vector(qvec, N, acl)
    I-->>H: cosine over the visible id set
    H->>H: weighted_fusion alpha=0.2 or rrf k=60
    H-->>P: candidates
    P->>R: rerank(query, candidates, depth=50)
    R-->>P: reordered by 8 pair features
    P->>X: dedup, order, pack k=8 within 6,000 tokens
    X-->>P: PackedContext with S# citation ids
    P->>G: generate(query, packed)
    G-->>P: Answer text, citations, usage
    P->>T: put(Trace with stage_ms per stage)
    P-->>U: Trace
```

### R3: the release gate on a pull request

The tolerances live in `scripts/run_eval.py`: evidence recall may drop by 0.02, full-chain
recall by 0.03 and answer correctness by 0.03. The frozen slice is reported on every run and
is never gated or tuned against. [ADR-0008](../20-decisions/0008-eval-gate-in-ci.md) records
why the gate is in CI.

```mermaid
sequenceDiagram
    autonumber
    actor Dev as Contributor
    participant GH as GitHub PR
    participant WF as eval-regression.yml
    participant RE as scripts/run_eval.py
    participant NR as nanorag
    participant BL as .github/eval-baseline.json

    Dev->>GH: open / push PR
    GH->>WF: pull_request event, also nightly 04:42 UTC
    WF->>RE: run_eval.py  (all 243 questions)
    RE->>NR: quickstart(**TUNED) then evaluate(pipe, questions, personas)
    NR-->>RE: per-question rows then summarize()
    RE->>BL: read prior metrics
    alt a gated metric drops beyond tolerance
        RE-->>WF: exit 1, RELEASE BLOCKED
    else within tolerance
        RE-->>WF: exit 0
    end
    WF->>RE: run_eval.py --slice frozen  (reported, never tuned against)
    WF->>GH: upsert "Eval gate" scorecard comment
    WF-->>GH: check fails if step 1 failed
    Note over Dev,BL: A deliberate change re-baselines in the same PR:<br/>python scripts/run_eval.py --baseline
```

### R4: a lab submission from a Discussion comment

Anyone can comment on a public discussion, so the comment body is untrusted. The job that runs
the code has no token and no network. The job that holds a write token never sees the code;
it reads a JSON report. The body reaches disk through an environment variable and never
appears on a shell command line. The security header of `.github/workflows/discussion-lab.yml`
has the full reasoning.

```mermaid
sequenceDiagram
    autonumber
    actor L as Learner
    participant D as GitHub Discussions
    participant T as job triage<br/>no permissions
    participant X as job execute<br/>no token
    participant S as Docker sandbox<br/>network none
    participant P as job post<br/>discussions write
    participant B as Hands-on Tracker board

    L->>D: comment with fenced code in "[submit · L03]" or "[arena · C02]"
    D->>T: discussion_comment event
    T->>T: lab id from title, body shaped like a submission?
    T-->>X: lab = L03
    X->>X: body via env var into submission.md, extract code block
    X->>S: docker run --read-only --cap-drop=ALL, 30 s kill
    S->>S: lab_sandbox.py runs public + hidden checks
    S-->>X: stdout line prefixed @@LAB-REPORT@@
    X-->>P: report.json artifact
    P->>P: lab_submission.py renders reply.md
    P->>B: tracker.py with PROJECT_TOKEN
    P->>D: addDiscussionComment as a threaded reply
    D-->>L: pass / fail with measurements
```

### R5: the agentic search loop

```mermaid
stateDiagram-v2
    direction LR
    [*] --> Decompose: question
    Decompose --> ChooseTool: sub-questions pending
    ChooseTool --> Retrieve: lexical, dense or hybrid
    Retrieve --> Sufficiency: append new hits with provenance
    Sufficiency --> Done: sufficient
    Sufficiency --> ChooseTool: missing sub-questions, re-anchor on original
    Retrieve --> Stopped: repeat detector
    Sufficiency --> Stopped: no new info, turn cap, wall clock, token budget
    Done --> Synthesise
    Stopped --> Synthesise: partial answer with a stated gap
    Synthesise --> [*]: AgentResult + turns
```

### R6: the index lifecycle

The incremental path handles an edited document. The rebuild path handles an encoder, chunker
or analyzer change. [ADR-0004](../20-decisions/0004-stable-chunk-ids.md) explains why stable
chunk ids keep the incremental path cheap.

```mermaid
stateDiagram-v2
    direction LR
    [*] --> Live: set_alias live to v1
    Live --> Incremental: document edited
    state Incremental {
        [*] --> HashDiff
        HashDiff --> Skip: content_hash unchanged
        HashDiff --> Upsert: changed, new chunk_id
        Upsert --> Tombstone: orphaned chunks
        Tombstone --> Compact
        Skip --> [*]
        Compact --> [*]
    }
    Incremental --> Live
    Live --> Rebuild: encoder, chunker or analyzer changed
    state Rebuild {
        [*] --> BuildV2: v2 alongside v1
        BuildV2 --> Shadow: evaluate frozen slice
        Shadow --> Swap: clean
        Shadow --> KeepV1: regression
        Swap --> [*]
        KeepV1 --> [*]
    }
    Rebuild --> Live
    Live --> Poisoned: new-encoder vectors written into v1
    Poisoned --> Live: mixed_version_check blocks release
```

## Deployment view

There is no server. Production is whatever runs the Python kernel: a laptop or a Codespace.
GitHub runs everything else, which is testing the code, publishing the docs and running the
course.

## Updating this page

Change a diagram in the same PR as the code it describes. The usual triggers are a new module
or seam implementation (Level 3, Level 4 and the import graph), a new workflow (the deployment
table) and a new external dependency (Level 1). Run `node tools/validate-mermaid.mjs` or
`make check` before pushing. Node colours come from the palette in `nanorag/viz.py`, as in the
README and overview.md.
